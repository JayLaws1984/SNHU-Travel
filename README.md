Interpreting user needs and implementing them into a program can be done by interviewing the customer or client, using surveys, test cases and user stories. By interviewing the client, we can find out what may have worked in the past and what aspects of the program may have been less successful. Test cases can be used to make sure each feature works correctly and meets the customer’s needs. In interviewing the customer, we can find out what their needs are and why they may be requesting a certain feature. This can then be incorporated into the program and additional features can be added that the customer may not be aware is possible. The use of user stories is helpful in giving us an idea of what the system will be used for and specific requests from those that will be using the program. Each request can be broken down into smaller tasks that can be completed during sprints. It allows the user to make requests for what they will be using the system for and how certain parts of the program will be helpful. 
I approach developing programs by first looking at the customer or clients’ needs. I can then take those requests and develop each task individually so that if any changes need to be made, they can be incorporated into the system. The Agile aspect I hope to incorporate into my future development work is sprint retrospective. It is important to review what worked, what was not successful and how I can improve. I want to make sure that with each project I improve in some aspect of my role. 
In order to be a good team member in software development it is important that I participate and learn as much as possible. Working with a team with different perspectives allows me the opportunity to provide input and learn different ways to accomplish a task. I want to listen and also make sure I am working to make sure I am contributing positive resolutions to the overall goal of the team. I also want to understand what the customer wants and how I can help in achieving those objectives.
